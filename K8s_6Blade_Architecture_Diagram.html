Storage design (no default Ceph)

  • etcd → dedicated local NVMe per CP (p99 fsync < 10 ms)
  • Vector DB / Redis → local NVMe persistent volumes
  • MinIO (on blades) → object store: model master copy (signed + checksummed), documents, backups
  • Model serving copy → pulled & verified to GPU host local NVMe
  • Observability → local NVMe + MinIO long-term tier

5Plane Boundary → Plane 2 GPU Inference (Separate Server)

LiteLLM router (blade-04) → mTLS + bearer token · OpenAI-compatible · inference VLAN → ExternalName / Endpoints → gpu-infer 10.30.0.20:8000
Cilium egress policy allows only router pods to reach the GPU host. Only a URL + credentials cross the boundary — the GPU backend is swappable without touching any microservice.

⛁ Plane 2 — Dedicated GPU Server (external to blade cluster)

Runs GLM-5.2 (744B MoE) that the CPU blades cannot host · tensor-parallel over NVLink · no content logging
Inference gateway — TLS · authN · rate-limit vLLM / SGLang — OpenAI-compatible server GLM-5.2 — FP8 ≈ 740–800 GB · INT4 ≈ 460–480 GB 8× 80 GB GPUs (illustrative) · TP=8 Local NVMe model store (verified pull from MinIO) DCGM exporter → blade Prometheus
One GPU server = single point of failure for the large model; a 2nd backend (router failover) delivers inference HA and ~2× throughput — GPU expansion roadmap.
